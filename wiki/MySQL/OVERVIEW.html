01 存储引擎与数据组织 STORAGE ENGINES & DATA ORGANIZATION

插件式架构是 MySQL 的根：SQL 层与存储层仅通过 sql/handler.h 的 handler 抽象解耦。数据最终以「表空间 → 段 → 页 → 记录」的层级落盘。

插件式引擎架构
sql/handler.h · include/mysql/plugin.h
handler 抽象类 + handlerton 注册表：open/read/write 与事务回调，引擎可插拔的唯一契约。
表空间 / 段 / 页
storage/innobase/fsp0fsp.*
表空间内部分配叶子段与非叶子段，按区（extent）管理，页是分配与 IO 的最小单位。
页结构
include/page0page.h
PAGE_LEVEL（B+树层号）、PAGE_N_DIR_SLOTS、FIL_PAGE_PREV/NEXT 双向链表。
记录格式
rem/rec.h
COMPACT/DYNAMIC 记录 5 字节头（REC_N_NEW_EXTRA_BYTES），删除标记、节点指针。
MyISAM 引擎
storage/myisam/
.MYD 数据 + .MYI 索引，keycache 键缓存，非事务的对比参照。
内存临时表
storage/temptable/ · sql/sql_tmp_table.cc
优化器排序/去重/物化的临时表引擎，内存放不下落盘。
02 索引 INDEXES

索引横跨三层：SQL 层用 KEY 描述、优化器用 range 区间使用、InnoDB 用 B+树物理实现。理解「描述 → 契约 → 实现」是索引源码的主线。

索引描述结构
sql/key.h
KEY（长度/列数/算法/基数）与 KEY_PART_INFO（偏移/前缀/排序方向/字符集比较）。
范围优化
sql/range_optimizer/
SEL_ARG 区间树合并 WHERE 条件，QUICK_RANGE 翻译成 key_range 交给引擎。
B+ 树实现
btr/btr0btr.cc · btr/btr0cur.cc
dict_index_t 描述树（根页/层数），btr_cur_search_to_nth_level 完成根到叶的查找。
二级索引回表
row/row0sel.cc
row_search_mvcc：二级索引记录附带主键列，再沿聚簇索引查完整行。
自适应哈希 / Change Buffer
btr0sea.* · ibuf0ibuf.*
AHI 为高频等值查询建内存哈希；Change Buffer 缓冲二级索引修改，减少随机 IO。
全文 / 空间 / 在线建索引
fts/ · ddl0impl-rtree.h · ddl/
全文倒排、空间 R-tree、ALTER 在线后台构建新索引树。
索引统计
dict0stats.*
后台采样各索引不同值数量 n_diff，填充 KEY::rec_per_key 供优化器估行数。
03 事务与并发控制 TRANSACTIONS & CONCURRENCY

ACID 在源码里是一条责任链：原子性靠 undo 与状态机，隔离性靠 ReadView 与行锁，持久性靠 redo，一致性由 binlog 两阶段提交兜底。

事务对象与状态机
include/trx0trx.h
trx_t（id/no/read_view）与 trx_state_t：NOT_STARTED→ACTIVE→PREPARED→COMMITTED。
事务系统
trx/trx0sys.*
trx_sys_t：max_trx_id 分配、rw_trx_list 活跃读写事务、serialisation_list 提交序。
SQL 层事务 / XA
sql/transaction.cc · sql/xa/
trans_begin/commit/rollback 协调引擎；XA 语句与崩溃后裁决（recovery.cc）。
行锁 / 间隙锁
lock/lock0lock.*
LOCK_S/X、LOCK_ORDINARY（next-key）、LOCK_GAP、LOCK_REC_NOT_GAP。
死锁检测
lock/lock0wait.cc
等待图上 DFS 找环，选择代价最小的事务回滚。
元数据锁 MDL
sql/mdl.h · sql/mdl.cc
保护表结构并发变更与查询的一致性，DDL 安全的关键。
两阶段提交 + 组提交
handler/ha_innodb.cc · sql/rpl_commit_stage_manager.h
innobase_prepare → binlog FLUSH/SYNC/COMMIT 三阶段 → innobase_commit，多事务合并落盘。
04 日志与恢复 LOGGING & RECOVERY

WAL 是持久性的骨架：数据页先改缓冲池、redo 先行落盘；undo 支撑回滚与 MVCC；binlog 服务复制。崩溃恢复以 mtr 为原子单位前滚 + 回滚。

redo log
log/log0log.* · log/log0write.cc
LSN 单调递增标记日志流，后台线程刷盘，log_t 全局对象管理。
崩溃恢复
log/log0recv.cc
启动时重放 redo 前滚，配合 undo 回滚未提交事务，恢复一致性。
undo log
trx/trx0undo.* · trx/trx0rec.*
TRX_UNDO_INSERT_REC=11 等记录类型；insert undo 只管回滚，update undo 承载版本链。
purge 清理
trx/trx0purge.cc
按全局最小活跃 ReadView 水位，物理删除不再可见的旧版本与已删行。
binlog
sql/binlog.cc · sql/binlog/ · libbinlogevents/
逻辑日志：事件格式定义与写入路径，复制与恢复的源头。
双写缓冲
buf/buf0dblwr.cc
防止页半写：先写双写文件再写数据文件，避免崩溃后页损坏。
缓冲池管理
buf/buf0buf.cc · buf0lru.cc · buf0rea.cc
LRU 淘汰、顺序预读、flush 列表刷脏，读路径的性能核心。
05 查询处理 QUERY PROCESSING

一条 SQL 走四段流水线：词法语法 → 语义解析 → 优化 → 执行。8.0 起优化器新增超图算法，执行器重构为火山式行迭代器。

词法 / 语法解析
sql/sql_lex.cc · sql/sql_yacc.yy
bison 语法生成 PT_* 语法树节点，预处理在 sql_prepare.cc。
语义解析
sql/sql_resolver.cc
表/列绑定、子查询展开，产出 Query_block 与 Item 表达式树。
优化器
sql/sql_optimizer.cc · sql/join_optimizer/
传统 join 枚举 + 超图优化器（hypergraph.cc），输出 AccessPath 计划树。
代价模型
sql/join_optimizer/cost_model.cc
行数 × 每行成本：基于 index dive 与统计估算访问路径代价。
执行器
sql/sql_executor.cc · sql/iterators/
行迭代器：嵌套循环、hash join、排序、窗口函数逐行拉取。
统计与直方图
sql/histograms/ · sql/dd/impl/tables/index_stats.cc
列直方图与索引统计支撑优化器做选择率估计。
06 复制与高可用 REPLICATION & HIGH AVAILABILITY

复制基于 binlog 事件流：GTID 标记事务、IO/SQL 线程应用、半同步与组复制提供强一致与自动故障转移。

GTID
sql/rpl_gtid_*.cc
全局事务标识：状态、执行、持久化（rpl_gtid_state / execution / persist）。
主从复制
sql/rpl_source.cc · sql/rpl_replica.cc · sql/rpl_rli.cc
binlog dump 线程、relay log 中继、IO 线程 + SQL 线程应用。
半同步复制
plugin/semisync/
主库等待至少一个从库确认 binlog 落盘后才提交，降低丢失窗口。
组复制 MGR
plugin/group_replication/
libmysqlgcs 自研组通信 + certification 冲突检测 + 分布式恢复。
并行复制
sql/rpl_mta_submode.cc · rpl_replica_commit_order_manager.cc
MTS 多线程应用 + 提交顺序管理，保证从库与主库事务顺序一致。
MySQL Router
router/
读写分离、负载均衡与故障转移的路由层，独立产品随仓库发布。
07 管理与监控 ADMINISTRATION & MONITORING

工程落地的支撑系统：数据字典统一元数据、权限认证保障安全、performance_schema 提供可观测性、字符集处理多语言排序。

数据字典
sql/dd/
8.0 起元数据统一进 InnoDB 系统表（mysql.*），取代 .frm 文件，支持原子 DDL。
权限与认证
sql/auth/
auth_acls 权限位、acl_table_user 用户表、认证插件（caching_sha2_password）。
字符集与排序
strings/ctype-*.cc
utf8mb4、gbk 等实现与 UCA 排序规则，影响索引比较与字符串函数。
性能监控
storage/perfschema/
performance_schema：等待、阶段、语句、内存事件采集，351 个源文件。
连接管理
sql/conn_handler/
Per_thread（每连接一线程）与 One_thread 模型，连接生命周期。
资源组与分区
sql/resourcegroups/ · sql/partitioning/
线程绑定 CPU 的资源组；分区裁剪与分区的 handler 适配。
MVCC 专题：快照读的可见性判定

MySQL 隔离性的理论核心：ReadView 判定 + undo 版本链 + purge 清理。与锁的分工——MVCC 管快照读（SELECT 不加锁），锁系统管当前读（UPDATE/DELETE / FOR UPDATE）。

① 视图对象 ReadView

  • m_creator_trx_id · 创建者事务
  • m_up_limit_id · 视图建立时最小活跃事务 id
  • m_low_limit_id · 视图建立时 max_trx_id
  • m_ids · 活跃事务有序数组（二分查找）
  • 源码：include/read0types.h

② 版本载体

  • 聚簇索引记录带 trx_id + roll_ptr
  • roll_ptr → undo 记录 → 更旧版本：版本链
  • 旧版本构造：row0vers.cc row_vers_build_for_consistent_read
  • 写路径：INSERT/UPDATE 写 undo（trx0undo.*）

③ 可见性判定算法

changes_visible(id): id < m_up_limit_id → 可见（已提交） id == m_creator_trx_id→ 可见（自己） id >= m_low_limit_id → 不可见（未提交） 否则 m_ids 二分查找 → 不在则可见

④ 隔离级别落点

  • READ_UNCOMMITTED · 不建视图，读最新
  • READ_COMMITTED · 每条语句重建 ReadView
  • REPEATABLE_READ · 事务内复用首个视图
  • SERIALIZABLE · 普通读升级 LOCK_S 当前读
  • 清理：trx0purge.cc 按最小活跃视图水位
