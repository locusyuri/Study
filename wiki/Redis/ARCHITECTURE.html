02 事件驱动核心：单线程为何能快 EVENT LOOP · ae.c

高性能的根基是 src/ae.c 的通用事件循环：文件事件（socket 就绪）+ 时间事件（定时任务）统一调度，回调里所有数据操作都在内存、无锁串行。

入口 ae.c:497 aeMain 调度 ae.c:365 aeProcessEvents 注册 ae.c:145 aeCreateFileEvent 服务启动 server.c:8038 main → :2999 initServer 休眠钩子 server.c:1947 beforeSleep 定期任务 server.c:1562 serverCron
  • 多路复用抽象：aeApiPoll 按平台编译切换实现 —— Linux ae_epoll.c，BSD/macOS ae_kqueue.c，兜底 ae_select.c / ae_evport.c，业务代码只看一套 ae API。
  • 主循环语义：aeMain 即 while(!stop) aeProcessEvents()；先处理就绪读事件，再处理写事件，保证"读完即回包"的低延迟。
  • 时间事件：serverCron 每秒约 10 次（hz），集中做定期工作 —— 过期键采样删除、rehash 推进、RDB 触发检查、客户端超时。
  • 休眠钩子：beforeSleep 在阻塞等待前处理待写客户端、AOF 刷盘、释放过期键，把"碎片活"塞进本来要阻塞的空窗。
03 8.x IO 线程化 IO THREADS · iothread.c

6.0 引入多线程 IO，8.x 重构为独立的 src/iothread.c：网络读写交给 IO 线程池，命令解析与执行仍由主线程串行 —— 吃满多核网卡中断，同时保住"执行无锁"语义。

启动 iothread.c:991 initThreadedIO 配置 server.h:2148 io_threads_num 待读 server.h:2108 clients_pending_read 待写 server.h:2109 clients_pending_write
  • 读侧：主线程把有数据待读的客户端批量分发给 IO 线程做 read()，解析留在主线程。
  • 写侧：响应先入输出缓冲，主线程按轮次把待写客户端交给 IO 线程批量 write()。
  • 边界：配置为 1（默认）即退化为纯单线程；线程数独立于主循环，无锁共享通过轮询 + 原子计数协调。

05 数据库层与过期机制 DATABASE & EXPIRATION

redisDb 持有键空间字典，默认 16 个库（server.h:2295 dbnum）；8.x 把主字典从单 dict 升级为多字典分片的 kvstore，扩容抖动进一步摊平。

写入 db.c:743 setKey 删除 db.c:926 dbDelete 惰性过期 db.c:2999 expireIfNeeded 定期过期 expire.c:287 activeExpireCycle 主字典 kvstore.c:197 kvstoreCreate 通知 notify.c:276 notifyKeyspaceEvent
  • 两阶段过期：读路径先查 expireIfNeeded（惰性）；serverCron 调 activeExpireCycle 随机抽样删除（定期），每次删除的 CPU 开销限定在预算内。
  • 8.x kvstore：主键空间拆成多个小 dict 分片，单次 rehash 的桶数更小、内存峰值更低，大库扩容不再"卡顿一下"。
  • 键空间通知：notifyKeyspaceEvent 把变更事件推给 Pub/Sub，是缓存失效、审计类场景的钩子。
06 持久化：RDB + AOF PERSISTENCE

RDB 负责"某一刻的全量快照"，AOF 负责"逐条写命令的增量"，二者可组合（aof-use-rdb-preamble 混合持久化）。落盘路径全部避开主线程。

RDB rdb.c:2180 rdbSave AOF 刷盘 aof.c:1399 flushAppendOnlyFile 触发计数 server.h:2367 dirty 文件名 server.h:2318 aof_filename · :2374 rdb_filename 工具 redis-check-rdb.c · redis-check-aof.c
  • RDB 快照：fork() 子进程利用 copy-on-write 落盘，父进程零阻塞；代价是写多时页复制带来瞬时内存上升。触发条件由 dirty（未保存改动数）与 save 点决定。
  • AOF 日志：每次写命令追加到缓冲区，flushAppendOnlyFile 按 appendfsync（always / everysec / no）刷盘；8.x 为 multi-part AOF + manifest 管理多文件。
  • AOF 重写：同样是 fork 子进程，将当前数据集压缩成最小命令集，避免日志无限膨胀。
  • 后台线程：bio.c 线程池承接 close fd、lazyfree、AOF fsync 等慢操作；大 key 删除走 lazyfree.c 异步释放，不阻塞主线程。
07 高可用与分布式 REPLICATION · SENTINEL · CLUSTER

复制解决"数据冗余"，哨兵解决"主挂了怎么办"，集群解决"单机放不下"（16384 个 hash slot，CRC16 分片）。

主从复制 replication.c · PSYNC 哨兵 sentinel.c · server.h:2073 sentinel_mode 集群开关 server.h:2613 cluster_enabled 集群实现 cluster.c · cluster_legacy.c · cluster_asm.c 发布订阅 pubsub.c:533 pubsubPublishMessage
  • PSYNC：全量同步传 RDB，增量同步靠 repl backlog 缓冲断线期间的写命令；replication.c 还负责把写命令传播给所有从库。
  • 哨兵：独立进程监控主从，主观下线 + 投票选主 + 自动切换，对外提供高可用入口。
  • 集群：cluster_legacy.c 承载槽位分配、gossip 集群视图与 MOVED/ASK 重定向；8.x 的 cluster_asm.c 为新一代集群代码组织，另配 cluster_slot_stats.c 做槽位统计。
  • Pub/Sub：7.x 起 PUBLISH 也会在集群内传播（pubsubPublishMessageAndPropagateToCluster）。

内存统计、淘汰、碎片整理、慢日志构成运维底座；事务、阻塞命令、ACL、脚本与模块构成生态入口。

  • zmalloc：在 malloc 前缀记录长度并累计 used_memory，可对接 jemalloc / tcmalloc —— 所有内存统计的源头。
  • 淘汰策略：LRU / LFU / random / noeviction 等 8 种，写入前由 performEvictions 按 maxmemory 逐出。
