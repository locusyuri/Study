Kafka 整体架构与核心概念
核心概念 → 源码映射

Kafka 是一套以「分区提交日志（Partitioned Commit Log）」为核心的分布式消息 / 流平台：消息按 Topic → Partition 落到只追加的日志文件中，靠副本复制保证不丢，由 KRaft 元数据集群统管全局，消费端以「组」为单位从日志的某个位置顺序拉取。

版本 4.4.0 共识 KRaft（无 ZooKeeper） 源码 Middleware/kafka 语言 Scala + Java

整体架构：两个角色 + 四层

ROLES & LAYERS

KRaft 时代集群只有两种进程角色，由 process.roles 决定，入口在 core/src/main/scala/kafka/server/KafkaRaftServer.scala；两者共享 SharedServer.scala 中的 Raft 客户端与 __cluster_metadata 元数据日志。

Broker

BrokerRole

处理生产 / 消费请求，管理分区日志、副本复制与协调器。

BrokerServer.scala

Controller

ControllerRole

集群元数据权威：建删主题、Leader 选举、ISR 维护、Broker 注册。

ControllerServer.scala + QuorumController.java

Combined（合并部署）

Broker + Controller

两者部署在同一进程，单机学习常用。

KafkaRaftServer 同时创建二者

一条消息的完整旅程

MESSAGE JOURNEY

把概念串成三条主链路：生产、消费、元数据传播。方括号内为沿途经过的关键类 / 文件。

生产路径

  • KafkaProducer.send()异步发送入口
  • RecordAccumulator.append()按分区攒批（batch.size）
  • Sender.runOnce()批量发送 + 重试
  • SocketServer → KafkaApis.handleProduceRequest()Broker 请求入口
  • ReplicaManager.appendRecords()Leader 分区追加
  • UnifiedLog.appendAsLeader()WAL 顺序写盘
  • DelayedProduceacks=all 等 ISR 追齐 → 推进 HW → 返回

消费路径

  • KafkaConsumer.poll()拉取循环
  • ConsumerCoordinator入组 / 分区分配
  • Fetcher发起 FetchRequest
  • KafkaApis.handleFetchRequest()Broker 侧处理
  • ReplicaManager.fetchMessages()读 HW 之前的已提交数据
  • UnifiedLog.read()Page Cache 读取
  • OffsetCommit位置写入 __consumer_offsets

元数据路径

  • QuorumController接收建主题 / ISR 等变更
  • 生成元数据记录如 PartitionRecord
  • RaftLog追加到 __cluster_metadata，多数派复制
  • MetadataPublisher推送增量 MetadataDelta
  • KRaftMetadataCache更新 Broker 本地缓存
  • Metadata 请求 / 心跳客户端实时感知变更
